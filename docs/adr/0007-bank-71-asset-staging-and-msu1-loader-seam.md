# Stage Level Assets in Game Pak RAM Bank `$71` via Relocatable Texture Tables and a 65816 `AssetSource` Seam

Status: accepted

For dynamically loaded isometric games (`gsu_iso` and `RamMapDemo`, while keeping legacy `IsoEngine` and `StarshipMap` on ROM Bank 4), level assets—the Texture Atlas (`.bin`), relocatable Texture Table (`.tab`), BGR555 palette (`.pal`), and Map Grid (`.map`)—are staged at runtime by the 65816 host CPU into **Game Pak RAM Bank `$71`** (`128 KB` expansion RAM via `ROM_EXPRAMSIZE = $07`) rather than bound at link time in ROM Bank 4 (`snes-sfx-demo` ADRs [0003](../../snes-sfx-demo/docs/adr/0003-non-square-textures-and-descriptors.md) and [0004](../../snes-sfx-demo/docs/adr/0004-virtual-slices-and-headless-texture-tooling.md)).

1. **Why `RAMB` + `LDB` instead of `ROMB` + `GETC`**: On the SuperFX (GSU / FX3), `ROMBR` + `R14` + `getc` can only address Game Pak ROM (`$00–$5F`) and cannot read Game Pak RAM (`$70–$71`). Conversely, `SCBR << 10` (`plot` / `rpix` targeting `$70:4000`) is independent of `RAMBR`. The Bank-`$71` trapezoid rasterizer (`draw_cached_trap_ram`) keeps stack frames (`R10`), `ARCH_TRAPS`, and working metadata in Bank `$70` (`RAMBR = 0`) and switches `RAMBR = 1` (`ibt r0, #1; ramb`) only around each scanline pixel span to fetch texels via `ldb (r11); color; plot` inside the 512-byte GSU instruction cache.
2. **Fixed Bank `$71` Layout & Relocatable `.tab` with Runtime `stride_shift`**: `sfx-studio` exports `<ATLAS>.tab` with an 8-byte header (`magic`, `entry_count`, `atlas_width`, `stride_shift`) followed by 0-based 8-byte `texture_descriptor` records, alongside `<LEVEL>.map` (`4×4` to `16×16` cells; `.sfxlevel` binds textures by symbolic name so atlas repacking never invalidates levels). Placing the Texture Atlas at `$71:0000–$71:7FFF` (`<= 32 KB`, leaving `$71:8000+` for `.tab`, `.map`, `.pal`, and ~28.5 KB of future game assets) makes every 0-based `atlas_offset` equal its exact 16-bit Bank `$71` pointer with zero per-trapezoid relocation math, while reading `stride_shift` from `.tab` lets levels swap atlases of different widths at runtime without reassembly.
3. **Unified 8-Byte 65816 `AssetSource` Seam for ROM and MSU-1**: Because both Cartridge ROM, MSU-1 (`$2001` `MSU_READ`), and Game Pak RAM (`$71`) sit on the SNES A-bus—and GSU bus arbitration (`GSU_SCMR` `RAN` bit) locks out 65816 SRAM access in GSU-2 / Mesen CE—the 65816 stages assets on the main thread under forced blank (`GSU_LOAD_LOCK`, `SFR.GO == 0`, clearing `GSU_SCMR` `RAN` during `$71` writes, restoring `DB = $80` after `MVN`, and re-enabling `GSU_SCMR` before `gsuOn`), decoupling `sfx_load_atlas` (with resident `atlas_id` deduplication) from `sfx_load_map`. Assets are indexed in an 8-byte `asset_entry` directory (`offset_lo`, `offset_hi`, `size_bytes`, `flags`) where `offset_hi:offset_lo` encodes `(^label : .loword(label))` for `asset_source_rom.i` (`MVN`) and a 32-bit `<rom>.msu` byte offset (`MSU_SEEK` `$2000–$2003` + 2-step WRAM-bounce DMA via `$2180`) for `asset_source_msu1.i`.
